# Finance OS - Full Project Handoff

Last updated: June 3, 2026

## 1. Project Summary

Finance OS is a founder-grade financial intelligence dashboard. It connects to payment gateways and uploaded financial files, normalizes transaction data into a common schema, computes financial intelligence metrics, and lets a founder ask plain-English finance questions through a Claude-powered AI endpoint.

The product is currently a single-tenant-per-user dashboard built on Supabase Auth and Supabase Postgres. Each user owns one organization, and all dashboard data hangs off `org_id`.

## 9. Auth and Request Security

Auth flow:

1. `proxy.ts` checks protected routes.
2. Unauthenticated users are redirected to `/auth/login`.
3. Authenticated users without an org are redirected to `/onboarding`.
4. Onboarding creates an `organizations` row.
5. Dashboard routes query data through the signed-in user/org relationship.

Latest security refactor:

New helper:

```text
lib/api/auth.ts
```

It exposes:

```ts
requireOrgAccess(orgId)
requireConnectorAccess(connectorId, { orgId?, type? })
isAuthFailure(result)
```

These helpers verify the current Supabase Auth user with the normal RLS-aware client before returning a service-role client for privileged server-side operations.

Why this matters:

Before the latest refactor, several API routes used the service-role client and trusted `org_id` or connector `id` from the request body. That could allow an authenticated user to read/write another org if they guessed IDs. The updated routes verify ownership before service-role access.

Protected API surfaces now include:
- Connector create/update/delete
- Individual connector sync
- Global org sync
- Transactions list
- Transactions summary
- CSV/Excel import

Public API exceptions in `proxy.ts`:
- `/auth/*`
- `/api/webhooks/*`
- `/api/cron/*`

Cron remains protected by `CRON_SECRET` inside the route.

## 10. Connector Sync Architecture

There are three layers:

### Layer 1: Gateway connector classes

Files:

```text
lib/connectors/razorpay.ts
lib/connectors/stripe.ts
lib/connectors/cashfree.ts
lib/connectors/payu.ts
lib/connectors/paytm.ts
lib/connectors/easebuzz.ts
```

These handle external API calls, auth headers/signatures, and pagination.

### Layer 2: Normalizer

File:

```text
lib/normalizer/index.ts
```

Returns:

```ts
type NormalizedTransaction = {
  external_id: string | null;
  type: "credit" | "debit";
  amount: number;
  currency: string;
  category: string | null;
  counterparty_name: string | null;
  description: string | null;
  source: string;
  status: "pending" | "completed" | "failed" | "refunded";
  transaction_date: string;
  metadata: Record<string, unknown>;
};
```

### Layer 3: Shared sync helper

File:

```text
lib/connectors/sync.ts
```

Main function:

```ts
syncConnectorTransactions({ supabase, connector, fromDate, toDate })
```

Responsibilities:
- Fetch gateway transactions.
- Capture endpoint-level warnings without failing the whole sync.
- Convert normalized transactions into database insert rows.
- Deduplicate by org-level external IDs using `getExistingExternalIds()`.
- Insert only new rows.
- Update `last_synced_at`.

Individual route files now delegate to:

```text
lib/api/connector-sync-route.ts
```

Example:

```ts
export async function POST(req: NextRequest): Promise<NextResponse> {
  return handleConnectorSyncRequest(req, "razorpay");
}
```

This greatly reduced duplicated route code.

## 14. Transactions APIs

List endpoint:

```http
GET /api/transactions?org_id=<uuid>
```

Supported filters:

```text
connector_id
source
type
from
to
search
limit
offset
sort
order
```

Validation hardening:
- `limit` is clamped between 1 and 500.
- `offset` cannot go below 0.
- Sort columns are allowlisted.
- Search is trimmed and sanitized.
- User/org access is verified before service-role querying.

Summary endpoint:

```http
GET /api/transactions/summary?org_id=<uuid>
```

Returns aggregate totals by source plus credits, debits, fees, net, and count.

## 15. Webhooks

Razorpay:

```http
POST /api/webhooks/razorpay
```

Uses `RAZORPAY_WEBHOOK_SECRET` for HMAC signature verification.

Latest hardening:
- Handles invalid signature buffer length safely.
- Only writes if the connector can be resolved unambiguously.
- If `x-razorpay-key-id` is present, it matches against connector config.
- If no key header is present, it only writes when there is exactly one active Razorpay connector.

Stripe:

```http
POST /api/webhooks/stripe
```

Uses `STRIPE_WEBHOOK_SECRET`.

Latest hardening:
- Only writes if the Stripe connector can be resolved unambiguously.
- If `stripe-account` is present, it matches against `config.account_id`.
- If no account header is present, it only writes when there is exactly one active Stripe connector.

## 23. Quick Recovery Checklist

If something breaks after deployment:

1. Check Vercel deployment logs.
2. Confirm all required env vars exist in Vercel.
3. Confirm Supabase migrations include migration 009.
4. Run `npm run build` locally with webpack.
5. Run `npm run lint`.
6. Test auth by logging in and opening `/dashboard`.
7. Test connector list and raw transaction API with a known org.
8. Test one connector sync with a short date range.
9. Inspect `connectors.status` and `last_synced_at`.
10. Check whether cron requests include `Authorization: Bearer <CRON_SECRET>`.
